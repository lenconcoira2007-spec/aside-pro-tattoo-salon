# ASIDE PRO Tattoo Salon

Учебный веб-проект тату-студии и документация к практической работе «Разработка документации проекта software с использованием базы данных (BD)».

## Содержание проекта

- `index.html` — главная страница с услугами, портфолио, преимуществами, отзывами, FAQ и контактами;
- `tattoo.html`, `piercing.html`, `removing.html` — страницы трёх направлений услуг;
- `feedback.html` — страница отзывов;
- `registration.html` — форма учебной заявки;
- `css/` — стили сайта;
- `JS/` — мобильная навигация, логика формы и работа с IndexedDB;
- `images/` — изображения проекта;
- `database/` — описание учебного хранилища;
- `docs/` — ТЗ, аудит, проектная документация, модель данных, диаграммы, тест-план и реестр доказательств;
- `tests/` — отдельная демонстрационная страница для просмотра и удаления тестовых заявок;
- `screenshots/` — папки для реальных скриншотов выполненных этапов;
- `.github/workflows/pages.yml` — автоматическая публикация сайта на GitHub Pages.

## Локальный запуск

1. Откройте папку проекта в VS Code.
2. Запустите локальный HTTP-сервер, например расширение Live Server.
3. Откройте `index.html` через адрес локального сервера.
4. Для проверки базы данных перейдите на `registration.html`.
5. Для просмотра и удаления тестовых заявок откройте `tests/database-demo.html`.

Не используйте `file://` для проверки IndexedDB и JavaScript ES-модулей. Используйте локальный HTTP-сервер.

## База данных (BD)

Учебная форма `registration.html` использует IndexedDB через `JS/booking.js` и `JS/booking-db.js`. База называется `aside-pro-tattoo-db`, версия 1. Она содержит хранилища `services` и `appointments`.

**Важное ограничение:** IndexedDB — локальное хранилище браузера. Заявки не отправляются владельцу студии, не синхронизируются между устройствами и не образуют общую серверную базу. Эта реализация предназначена для демонстрации учебного цикла «ввод → проверка → сохранение → чтение → удаление». Для реального сервиса потребуется серверная БД, API и защищённый административный доступ.

## Тестирование и доказательства

План проверок находится в `docs/test-plan.md`; предварительные результаты статической проверки — в `docs/verification-results.md`. Браузерные проверки, действия GitHub и публикация должны фиксироваться реальными скриншотами в папках `screenshots/`.

Не отмечайте тест как пройденный и не добавляйте изображение вместо скриншота фактического действия. Используйте только вымышленные тестовые данные.

## GitHub Pages

Workflow запускается при push в ветку `main` или вручную через GitHub Actions. Он публикует только HTML-страницы, `css/`, `JS/` и `images/`; документация, скриншоты и тестовая страница управления заявками не включаются в публичный сайт.

В настройках репозитория откройте **Settings → Pages** и выберите **GitHub Actions** в качестве источника публикации, если GitHub не применил его автоматически. Фактический URL появится после успешного workflow.

## Перед публичной публикацией

Проверьте официальное написание бренда, контактные данные, адрес, цены и право использовать фотографии/отзывы. В исходном макете присутствуют контактные данные и адрес, достоверность которых владельцем не подтверждена. Не публикуйте реальные персональные данные клиентов.
