# Проектирование базы данных (BD)

## 1. Выбор хранилища

Для статического сайта на GitHub Pages используется IndexedDB. Это встроенное в браузер объектное хранилище, доступное из JavaScript. Оно позволяет продемонстрировать создание БД, добавление, чтение и удаление записей без отдельного сервера. Оно не является реляционной SQL-СУБД и не обеспечивает централизованное хранение данных.

## 2. Логическая модель

### `services`

| Поле | Тип | Ключ | Обязательное | Пример |
|---|---|---|---|---|
| `id` | string | PK | да | `tattoo` |
| `name` | string | — | да | `Татуировки` |
| `priceLabel` | string | — | нет | `от 40 €` |
| `active` | boolean | — | да | `true` |
| `sortOrder` | number | — | да | `1` |

### `appointments`

| Поле | Тип | Ключ | Обязательное | Пример |
|---|---|---|---|---|
| `id` | number | PK, autoIncrement | да | `1` |
| `clientName` | string | — | да | `Тестовый клиент` |
| `contact` | string | — | да | `+37360000000` |
| `serviceId` | string | логическая ссылка | да | `tattoo` |
| `comment` | string | — | нет | `Хочу консультацию по эскизу` |
| `preferredDate` | string | — | нет | `2026-12-01` |
| `preferredTime` | string | — | нет | `15:30` |
| `createdAt` | string ISO 8601 | индекс | да | `2026-11-16T12:00:00.000Z` |
| `status` | string | индекс | да | `new` |

## 3. Связь

`services (1) ─── (N) appointments`: одна услуга может быть выбрана во многих заявках. Каждая заявка хранит `serviceId`. Проверка наличия услуги выполняется приложением перед записью.

## 4. Индексы

Для `appointments` предлагаются индексы `byService` по `serviceId`, `byCreatedAt` по `createdAt`, `byStatus` по `status`. Индексы нужны для упорядоченного и фильтруемого чтения при демонстрации.

## 5. Правила записи

1. Проверить обязательные поля формы.
2. Обрезать начальные и конечные пробелы.
3. Убедиться, что `serviceId` существует и услуга активна.
4. Создать заявку со статусом `new` и `createdAt`.
5. Записать объект транзакцией IndexedDB.
6. Показывать сообщение об успехе только после события `transaction.oncomplete`.
7. При ошибке показать сообщение об ошибке, не сообщая об успешной записи.

## 6. Ограничения

- Данные локальны для браузера и origin сайта.
- Разные устройства/браузеры не видят одну и ту же базу.
- Очистка данных сайта может удалить данные.
- Нельзя считать заявку подтверждённой записью на процедуру.
- Не использовать реальные персональные данные на публичной странице просмотра.
