# Проектная документация ASIDE PRO Tattoo Salon

**Редакция:** 1.1, итоговая  
**Дата:** 16 ноября 2026 г.

## 1. Назначение проекта

ASIDE PRO Tattoo Salon — учебный адаптивный веб-сайт тату-студии. Он представляет три направления услуг (татуировка, пирсинг, лазерное удаление), портфолио, преимущества студии, отзывы, FAQ, контакты и форму отправки заявки.

## 2. Исходное состояние

Исходный архив содержит шесть HTML-страниц, `css/style.css`, `JS/slider.js` и локальные изображения. Исходная форма была демонстрационной и не сохраняла заявки в базе данных. Полный аудит описан в `analysis-before-change.md`.

## 3. Реализованные в рабочей копии изменения

- Подготовлена форма `registration.html` с обязательными полями имени, контакта и услуги.
- `JS/booking.js` загружает список услуг, проверяет форму, вызывает сохранение и показывает результат только после завершения операции.
- `JS/booking-db.js` создаёт IndexedDB `aside-pro-tattoo-db` версии 1 с хранилищами `services` и `appointments`.
- `tests/database-demo.html` и `tests/database-demo.js` предназначены для учебного чтения и удаления локальных тестовых заявок.
- В интерфейсе формы указано, что данные остаются в текущем браузере и не подтверждают реальную запись.

Факт функциональной проверки в реальном браузере следует подтвердить отдельно; см. `verification-results.md` и `test-plan.md`.

## 5. Модель данных

База `aside-pro-tattoo-db` версии 1 содержит:

- `services` — справочник доступных услуг;
- `appointments` — заявки посетителей.

Связь логическая: одна услуга может быть выбрана в нескольких заявках. `appointments.serviceId` содержит `services.id`. Подробная схема, поля и индексы описаны в `database-design.md`, диаграмма — `er-diagram.png` / `er-diagram.mmd`.

## 6. Ограничения выбранной модели

IndexedDB работает на стороне браузера. Данные не отправляются владельцу студии, не синхронизируются между устройствами и могут быть удалены при очистке данных сайта. Эта реализация предназначена для демонстрации учебного сценария «форма → проверка → сохранение → чтение/удаление», а не для реального обслуживания клиентов. Для промышленной версии понадобится серверная БД и защищённый API.

## 7. Запуск

1. Распаковать ZIP.
2. Открыть папку проекта в VS Code.
3. Запустить локальный HTTP-сервер (например, Live Server).
4. Открыть `index.html`.
5. Перейти на `registration.html`, проверить форму с вымышленными данными.
6. Открыть `tests/database-demo.html`, проверить список и удаление заявок.

Для ES-модулей и IndexedDB рекомендуется HTTP-сервер, а не открытие HTML двойным щелчком.
