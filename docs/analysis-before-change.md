# Предварительный аудит исходного сайта ASIDE PRO Tattoo Salon

**Основание:** первоначальный архив сайта ASIDE PRO Tattoo Salon.  
**Статус:** аудит исходного состояния, до внесения изменений.  
**Важно:** это описание того, что уже обнаружено в исходниках, а не заявление о выполненной доработке.

## 1. Состав проекта

В архиве обнаружено шесть HTML-страниц, одна основная таблица стилей и один небольшой JavaScript-файл:

| Файл | Назначение |
|---|---|
| `index.html` | Главная страница: услуги, преимущества, портфолио, процесс записи, отзывы, FAQ и контакты |
| `tattoo.html` | Описание услуги татуировки и ориентировочных цен |
| `piercing.html` | Описание пирсинга и ориентировочных цен |
| `removing.html` | Описание лазерного удаления и ориентировочных цен |
| `feedback.html` | Статические карточки отзывов |
| `registration.html` | Форма заявки на консультацию/услугу |
| `css/style.css` | Общие стили, сетки и адаптивные правила |
| `JS/slider.js` | Открытие/закрытие мобильного меню навигации |

Проект содержит локальные изображения, включая логотип, фотографии работ и графические материалы.

## 2. Что уже реализовано

- Одностраничная главная страница с секциями услуг, портфолио, преимуществ, отзывов, FAQ и контактов.
- Отдельные страницы трёх направлений: татуировка, пирсинг и удаление тату.
- Отдельная страница с отзывами.
- Визуально оформленная форма заявки с полями имени, контакта, услуги и комментария.
- Общая навигация и отдельные ссылки на страницы услуг.
- Адаптивные CSS-правила с контрольными ширинами 900 px и 620 px.
- Атрибуты `alt` у основных изображений, указанных в HTML.

## 3. Что пока не реализовано

- Форма `registration.html` не отправляет данные на сервер и не сохраняет их в базе. При отправке вызывается `alert()`.
- В проекте не обнаружены SQL-файлы, API, серверная часть или реализация IndexedDB.
- Каталог услуг и отзывы находятся непосредственно в HTML-разметке.
- Нет административного интерфейса для управления заявками.
- Нет механизма общей синхронизации заявок между браузерами и устройствами.

Следовательно, на момент аудита сайт является статическим фронтенд-проектом. Нельзя утверждать, что заявка уже сохраняется или доступна владельцу салона.

## 4. Данные, требующие подтверждения

В исходной главной странице приведены адрес «Краснопрудная улица, 28, Москва», номер телефона с кодом `+7` и адрес `TattooSalon@mail.ru`. Эти сведения присутствуют в исходном HTML, но их достоверность заказчиком не подтверждена. Перед публикацией их необходимо проверить или заменить на реальные данные.

В исходниках бренд отображается преимущественно как `Tattoo Salon`, тогда как в задании проект обозначен как `ASIDE PRO Tattoo Salon`. Название и написание логотипа следует унифицировать после подтверждения владельцем проекта.

## 5. Решение для текущей версии

В качестве базового варианта предлагается IndexedDB — встроенное браузерное хранилище. Такой вариант совместим со статической публикацией на GitHub Pages и близок к технологии, использованной в предоставленном образце работы по автосервису.

Предлагаемая модель включает два хранилища:

- `services` — справочник услуг;
- `appointments` — заявки посетителей.

У каждой заявки будет ссылка `serviceId` на выбранную услугу, дата создания и начальный статус `new`. В форме будет показано сообщение о принятии заявки **в локальное хранилище**, а не о подтверждённой записи на реальное время.

**Ограничение:** IndexedDB хранит данные в профиле конкретного браузера на конкретном устройстве. Это не серверная база и не общий кабинет салона. Для реального коммерческого приёма заявок потребуется серверная БД/API и защищённый административный доступ.
