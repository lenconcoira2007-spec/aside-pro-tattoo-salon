## 2.3. Требования к BD

В текущей реализации используется IndexedDB — встроенное объектное хранилище браузера. Выбор согласован с техническим подходом примера проекта «Автосервис», где данные также хранятся локально в браузере. IndexedDB не является SQL Server/MySQL и не предоставляет общего серверного хранилища.

**Имя БД:** `aside-pro-tattoo-db`; **версия:** 1.

| Хранилище | Поля | Ключ / назначение |
|---|---|---|
| `services` | `id`, `name`, `priceLabel`, `active`, `sortOrder` | `id` — строковый первичный ключ; справочник доступных услуг. |
| `appointments` | `id`, `clientName`, `contact`, `serviceId`, `comment`, `preferredDate`, `preferredTime`, `createdAt`, `status` | `id` — автоинкремент; `serviceId` — логическая ссылка на `services.id`. |

**Связь:** одна услуга может быть указана в нескольких заявках (1:N). IndexedDB не создаёт внешний ключ как реляционная СУБД; перед сохранением приложение проверяет существование и активность выбранной услуги. Для списка заявок создаются индексы по `serviceId`, `createdAt`, `status`.

**Ограничения:** данные доступны только в том браузере/профиле и на том origin, где они созданы. Очистка данных сайта может удалить их. Для реального коммерческого использования требуется серверная БД, API, контроль доступа и политика обработки персональных данных.
