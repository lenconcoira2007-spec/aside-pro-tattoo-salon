# Техническое задание ASIDE PRO Tattoo Salon

Версия 1.0 · 16.11.2026 · Учебный проект

## 1. Имя сайта
Проектное имя: aside-pro-tattoo-salon. Публичный URL GitHub Pages будет подтверждён после успешной публикации.

## 2. Название сайта
ASIDE PRO Tattoo Salon.

## 3. Назначение и цель
Представление тату-студии в сети Интернет: описание татуировок, пирсинга и лазерного удаления; демонстрация портфолио и отзывов; ответы на вопросы; контактная информация; форма заявки на консультацию. Цель учебной версии — продемонстрировать веб-проект с базой данных (BD) и его документацию.

## 4. Язык
Основной язык текущей версии — русский. Дополнительные языки не входят в текущий объём.

## 5. Ключевые слова
ASIDE PRO, тату-салон, татуировка, пирсинг, удаление татуировки, лазерное удаление, эскиз тату, запись на консультацию. Позиции поисковой выдачи не гарантируются.

## 6. Текстовая и графическая информация
Используются материалы исходного архива. Права на фотографии, достоверность отзывов, адрес, контакты и цены должен подтвердить владелец проекта до публичной коммерческой эксплуатации.

## 7. Целевая аудитория
Совершеннолетние пользователи, интересующиеся татуировками, пирсингом и удалением татуировок. Сайт не заменяет консультацию специалиста.

## 8. Состав страниц
1. index.html — главная: услуги, преимущества, портфолио, отзывы, FAQ, контакты.
2. tattoo.html — услуга татуировки.
3. piercing.html — услуга пирсинга.
4. removing.html — лазерное удаление.
5. feedback.html — отзывы.
6. registration.html — форма заявки.

## 9. Навигация
С каждой внутренней страницы доступен переход на главную. Основная навигация ведёт к услугам, портфолио, отзывам, контактам и форме записи. Мобильное меню должно оставаться доступным.

## 10. Блок-схема
Карта переходов находится в docs/site-map.mmd. Главная страница содержит переходы к ключевым разделам и услугам.

## 11. Объём сайта
Не фиксируется в мегабайтах. Изображения оптимизируются без заметной потери качества.

## 12. Оформление изображений
Содержательные изображения должны иметь осмысленный alt-текст. Декоративные изображения могут иметь пустой alt.

## 13. Скорость загрузки
Сайт должен быть пригоден для обычного домашнего и мобильного соединения. Числовые показатели скорости указываются только после измерения.

## 14. Разрешение
Контрольные ширины: 320, 360, 390, 768, 1024 и 1440 CSS px.

## 15. Минимальная ширина
320 CSS px. Горизонтальная прокрутка основного содержимого не допускается; результат подтверждается тестированием.

## 16. Браузеры
Актуальные стабильные Google Chrome, Microsoft Edge, Mozilla Firefox, Safari на iOS и Chrome на Android. Internet Explorer не поддерживается. Версия браузера фиксируется в журнале тестирования.

## 17. Цветовая палитра
Сохраняется тёмная палитра исходного дизайна: графитовый фон, светлый текст и красно-коралловый акцент.

## 18. Фон
Единый тёмный фон страниц с контрастными поверхностями карточек и секций.

## 19. Шрифты
Системный стек Arial/Helvetica, sans-serif. Размеры должны оставаться читаемыми на мобильных и настольных экранах.

## 20. Регистрация в каталогах
Не входит в учебный объём.

## 21. Реклама и продвижение
Платная реклама и гарантированное поисковое продвижение не входят в ТЗ.

## 22. Сроки
Последовательность: аудит → согласование ТЗ → реализация формы и BD → тестирование → GitHub → публикация → отчёт. Точные даты задаются преподавателем.

## 23. Передача проекта
Передаются исходный код, документация, модель данных, тест-план, подтверждающие скриншоты, URL репозитория и URL GitHub Pages после публикации; дополнительно формируется ZIP.

## 24. Сопровождение
Постоянное сопровождение после учебной сдачи не входит в объём.

## 25. Дополнительные условия
- Единый стиль и навигация на всех страницах.
- Подтверждение контактных данных, цен и прав на изображения перед публичным использованием.
- Только вымышленные тестовые заявки.
- Запрещено добавлять пароли, токены и персональные данные в репозиторий.
- Интерфейс должен уточнять, что заявка сохраняется в локальное учебное хранилище и не подтверждает реальную запись.
- Результаты тестов фиксируются после их реального выполнения.

## 26. Структура
Проект содержит HTML-страницы, css, JS, images, database, docs, tests, screenshots и .github/workflows.

## 27. Функциональные требования
FR-01: доступ к шести страницам; FR-02: навигация между разделами; FR-03: обязательные имя, контакт и услуга; FR-04: необязательные дата, время и комментарий; FR-05: загрузка услуг из хранилища; FR-06: сохранение заявки в IndexedDB; FR-07: просмотр и удаление тестовых заявок; FR-08: понятное сообщение об ошибке и указание локального характера хранения.

## 28. Требования к BD
Учебная БД: aside-pro-tattoo-db, версия 1. Object stores: services и appointments. Связь 1:N моделируется полем serviceId. IndexedDB не является SQL-СУБД и не обеспечивает синхронизацию между устройствами. Серверная БД/API не входит в текущую реализацию.

## 29. Критерии приёмки
Проверить все страницы, ресурсы, адаптивность, валидацию, создание и чтение заявки, сохранение после обновления, удаление, документацию, GitHub Actions и опубликованный URL. Статус Passed ставится только после реальной проверки.

## 30. Допущения
Преподаватель должен подтвердить, что IndexedDB подходит вместо SQL Server/MySQL. Владелец проекта должен подтвердить адрес, контакты, цены, бренд и права на материалы.
