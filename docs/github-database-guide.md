# Файлы базы данных в GitHub: назначение и содержание

В репозитории база данных описана и реализована несколькими связанными файлами. Каждый файл отвечает за отдельную часть работы.

## 1. `JS/booking-db.js` — программный код базы данных

Это основной JavaScript-модуль, который создаёт и открывает IndexedDB с именем `aside-pro-tattoo-db`, версия 1.

В нём создаются два хранилища:
- `services` — справочник услуг;
- `appointments` — заявки.

Также в модуле создаются индексы и реализованы функции:
- `openBookingDatabase()` — открыть базу и создать структуру при первом запуске;
- `getServices()` — получить список услуг;
- `createAppointment()` — сохранить заявку;
- `getAllAppointments()` — получить сохранённые заявки;
- `deleteAppointment()` — удалить одну заявку;
- `clearAppointments()` — очистить список заявок.

**Как объяснить:** этот файл содержит программные команды, благодаря которым браузер создаёт базу и выполняет операции с записями.

## 2. `database/README.md` — краткий паспорт базы

Файл в папке `database` кратко объясняет, какая технология используется, как называется база, какие хранилища в ней созданы, как связаны услуги и заявки и какие операции доступны.

**Как объяснить:** это краткое текстовое описание базы, чтобы по структуре репозитория было понятно, где находится BD и как она устроена.

## 3. `docs/database-design.md` — подробное проектирование

Здесь описана логическая модель двух хранилищ:
- поля `services`: `id`, `name`, `priceLabel`, `active`, `sortOrder`;
- поля `appointments`: `id`, `clientName`, `contact`, `serviceId`, `comment`, `preferredDate`, `preferredTime`, `createdAt`, `status`.

Для каждого поля указаны тип, назначение, ключ и необходимость заполнения. В документе также объяснены связь 1:N, индексы и порядок сохранения заявки.

**Как объяснить:** этот документ показывает, какие данные хранятся, какие поля являются ключами и каким образом заявка связывается с выбранной услугой.

## 4. `docs/er-diagram.mmd` — исходник ER-диаграммы

Это текстовое описание диаграммы в формате Mermaid. В нём указаны сущности `SERVICES` и `APPOINTMENTS`, их поля и связь один-ко-многим.

**Как объяснить:** это исходный файл схемы. Его можно редактировать как текст, а затем получать из него визуальную диаграмму.

## 5. `docs/er-diagram.png` — готовая ER-диаграмма

Это графическое представление той же модели. На схеме видно, что одна услуга может быть связана с несколькими заявками. Поле `serviceId` в заявке содержит идентификатор услуги.

**Как объяснить:** PNG удобно вставлять в отчёт и показывать на защите, потому что структура и связь видны визуально.

## 6. `JS/booking.js` — подключение базы к форме

Этот модуль связывает форму на странице `registration.html` с функциями из `booking-db.js`. Он загружает доступные услуги, проверяет заполнение полей и вызывает сохранение заявки.

**Как объяснить:** этот файл отвечает за взаимодействие интерфейса с базой: пользователь заполняет форму, а JavaScript передаёт данные в IndexedDB.

## 7. `tests/database-demo.html` и `tests/database-demo.js` — просмотр структуры и записей

Эта страница открывает ту же IndexedDB в текущем браузере и показывает фактические хранилища, ключи, индексы, поля и количество записей. Ниже отображается список заявок; запись можно удалить.

**Как объяснить:** это страница для проверки результата. Она позволяет убедиться, что база открывается, структура существует, а добавленные записи читаются и удаляются.

В матрице указано, какой файл реализует конкретное требование, как его проверить и где находится подтверждающий скриншот.

**Как объяснить:** по этой таблице можно проследить путь от требования к файлу программы и тесту, который подтверждает его работу.

## Важное ограничение хранения

В текущей версии используется IndexedDB — локальное хранилище браузера. Код и документация находятся в GitHub, но пользовательские заявки не записываются в репозиторий GitHub. Они остаются в браузере и не синхронизируются между устройствами. Для общей базы заявок потребуется серверная БД и API.
